    Dijkstra vs Greedy Best-First Search

    Dijkstra chooses the unsettled node with the smallest total cost from the source, so its route is optimal for the selected graph weights. Greedy Best-First Search chooses the frontier node that appears closest to the destination by straight-line distance. It ignores the cost already traveled, so it can reach the destination after exploring fewer nodes but is not guaranteed to find the shortest route. Both use the same directed corridors and selected objective; the straight-line heuristic only guides Greedy BFS.

    What this experiment can establish

    Dijkstra finds an optimal route in the supplied finite, nonnegative weighted graph. The Python implementation was checked against independent Floyd-Warshall results for all 169 origin–destination pairs under both objectives. Human superiority or inferiority cannot be concluded until real participant observations are added.

    Road-level turn history is not retained when separately computed corridors are concatenated. Last-mile access, ambulance availability, dispatch delay, live traffic and emergency-vehicle permissions are outside this model. BC is a teaching connection, so closing it does not simulate every road segment a corridor might share.
